## 2. Duplicate Detection Rules by Entity

### 2.1 User Accounts
- **Primary Match Key:** Normalized lowercase email (`LOWER(TRIM(email))`).
- **Secondary Match Key:** 10-digit mobile phone number (`TRIM(phone)`).
- **Collision Strategy:**
  1. *Same Email Found:* Do NOT create a duplicate user. Link the historical records to the existing user ID. Log the occurrence in `migration_logs`.
  2. *Different Email, Same Phone:* Flag for manual review if names differ significantly. Otherwise, create a unique account.
  3. *Unique Email & Phone:* Insert as a new user with generated sequential ID.

### 2.2 Sellers & Institutes
- **Primary Match Key:** Linked `user_id` (via user email match).
- **Secondary Match Key:** Normalized Business Name + City (e.g. "Vinayak Computer Education Center" vs "VCEC - Vinayak").
- **Collision Strategy:**
  1. *Verified Link:* If the seller's user already exists (e.g. Vinayak), link courses and business listings to the existing `sellers.id`.
  2. *Uncertain Similarity:* Do not automatically merge two different businesses based on partial name match. Insert as an independent new seller with an autogenerated `seller_code` (e.g. `DC-SELL-000201`).

### 2.3 Courses
- **Match Key:** `seller_id` + Normalized `title`.
- **Collision Strategy:**
  - If a course with the exact same title already exists under the same seller, do NOT overwrite. Skip insertion and link dependent contents to the existing course.

### 2.4 Business Directory Listings
- **Match Key:** `seller_id` + Normalized `business_name`.
- **Collision Strategy:**
  - If the seller already has an active listing with the same business name, update any missing contact fields or preserve as distinct branch.

## 3. Real Collision Investigation: The "VCEC / Vinayak" Case

During schema inspection, a notable candidate was identified:
- **New Database:**
  - User ID: 15 (`vinayak@vcec.in`)
  - Seller ID: 6 (`DC-SELL-000115`, `VCEC - Vinayak`, Ahmedabad)
- **Old Database (`digitxix_elm`):**
  - `dc_affiliate` ID: 10 (`Vinayak Computer Education Center`, `vinayak_23@yahoo.co.in`, Phone `9825441584`, Ahmedabad)

### Resolution Decision:
Because the emails differ (`vinayak@vcec.in` vs `vinayak_23@yahoo.co.in`), the migration engine will:
1. Create a separate account for `vinayak_23@yahoo.co.in` by default, preserving both records cleanly without overwriting Seller ID 6.
2. Store the historical mapping in `migration_id_mappings`.
3. Provide an option in the migration dashboard for an admin to merge them post-migration if the owner confirms they are the same person.
